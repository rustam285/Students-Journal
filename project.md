# project.md — контекст проекта «Журнал студентов ЧелГУ» (Students-Journal)

> Самодостаточная справка для новой сессии. Прочитай её целиком перед работой.

## 1. Что это

Веб-приложение (журнал/CRM) для преподавателя: учёт посещаемости и успеваемости
студентов ЧелГУ. Группы, студенты, предметы, занятия (пары), оценки, бонусы,
статистика, экспорт отчётов, импорт студентов из CSV/XLSX, переход на новый
учебный год (перевод групп + выпуск).

- Локальная рабочая копия: `D:\!!Проекты\Журнал студентов ЧелГУ (Next.js)`
- Репозиторий: https://github.com/rustam285/Students-Journal.git (ветка `main`)
- Прод: Windows Server, путь `C:\Journal\Journal\Students-Journal`,
  сайт **http://tfcsu.ru:3000** (A-запись → 178.46.164.93), порт 3000 в файрволе.

## 2. Стек

- **Next.js 14.2 (App Router)**, TypeScript strict, React 18
- **Tailwind CSS + shadcn/ui** (компоненты в `src/components/ui/`), тёмная тема
- **Prisma ORM + PostgreSQL**. БД — **встроенный** `embedded-postgres@18.4.0-beta.17`
  (бинарники в `node_modules`, кластер в `pgdata/`, порт **5433**,
  логин/пароль `journal`/`journal`, база `students_journal`)
- **Auth.js (NextAuth v5 beta)** — credentials-провайдер, JWT-сессии, bcryptjs
- SheetJS (`xlsx`) — импорт студентов; Recharts — графики; date-fns; zod
- Пакетный менеджер — **pnpm**

## 4. Модель данных (Prisma, ключевое)

- `User` — role: `ADMIN | TEACHER | STUDENT`; `mustChangePassword`,
  `failedLoginAttempts`, `lockedUntil`; мягкое удаление `deletedAt`.
  Student может иметь связанный User-аккаунт (`Student.userId`).
- `Term` — семестры с датами начала/конца, `isActive`.
- `Group` — `course` (текущий курс) и `graduationCourse` (выпускной курс,
  настраиваются независимо — логика перевода года это проверяет),
  классный руководитель (`homeroomTeacher`), доп. преподаватели (`TeacherGroup`);
  `scheduleGroupId` — сопоставление с группой сайта расписания
  (для автозаполнения журнала; выставляется при первом заполнении).
  У `User` аналогичное поле `scheduleTeacherId` — id преподавателя расписания.
- `Student` + `StudentGroup` (m2n студент↔группа), `deletedAt`.
- `Lesson` — занятие: группа, семестр, преподаватель, предмет (опционально),
  дата, номер пары (расписание пар в `src/lib/constants.ts`), тема.
- `AttendanceRecord` — `status: PRESENT|ABSENT|LATE`, `grade` (1–100),
  `bonusPoints`, `comment`; уникальность (lessonId, studentId).
- `Subject` — предмет преподавателя (`@@unique([name, teacherId])`), есть флаг
  обязательности (см. страницу subjects).
- `GroupAccessRequest` — запрос преподавателя на доступ к группе (PENDING/…).
- `AuditLog` — журнал действий (пишется через `src/lib/audit.ts`).

### Автозаполнение журнала из расписания (интеграция с сайтом расписания)

Кнопка «Заполнить» на страницах журнала и календаря (общий компонент
`src/components/fill-journal-dialog.tsx`) → диалог с пресетами периодов (сегодня,
завтра, на дату, эта/следующая/две недели, месяц, с—по) и сводкой-подтверждением
«Проверьте, всё ли выбрано верно» перед выполнением. Занятия тянутся сервером
из JSON-API сайта расписания (`/api/teacher_schedule/` — «для копирования 12»
того проекта) и создаются в журнале: только пары выбранной группы у
сопоставленного преподавателя, тема = дисциплина, заметки = «формат, ауд. N»,
предмет создаётся автоматически (если нет), посещаемость — всем «Присутствует».
Повторное заполнение идемпотентно (существующие занятия группы на эту дату/пару
пропускаются), «ЭКЗ»-слоты пропускаются. Режим «Все мои группы»
(`fillAllGroupsFromSchedule`) заполняет разом все группы с доступом пользователя:
расписание скачивается один раз, группы сопоставляются по сохранённому id или
названию, несопоставленные перечисляются в результате. Сопоставления
(преподаватель по ФИО «Фамилия И.О.», группа по названию без регистра/е/ё)
подбираются автоматически, при несовпадении выбираются вручную один раз и
запоминаются (`User.scheduleTeacherId`, `Group.scheduleGroupId`) — id стабильны,
переименования групп на сайте расписания не ломают связь. База API — env
`SCHEDULE_API_URL` (по умолчанию `http://127.0.0.1:8100` — прод «тот же хост»;
локально `http://127.0.0.1:8000`). Хост берётся только из env (SSRF исключён),
диапазон > 31 дня режется на окна (лимит API).

## 5. Роли и права

- **ADMIN** — всё: пользователи, группы, предметы, перевод учебного года, аудит.
- **TEACHER** — свои группы (homeroom + доп. + по запросу), журнал, студенты,
  предметы, импорт.
- **STUDENT** — dashboard, календарь, «мои записи» (my-records), профиль.
- Проверки ролей делаются в server actions / route handlers через
  `await auth()` + `session.user.role`. Страницы под логином — группа маршрутов
  `(protected)`; неавторизованных middleware редиректит на `/login`.
- После создания пользователя админом ставится `mustChangePassword=true` →
  принудительная смена пароля (`/change-password`).

## 6. Запуск и команды

```bash
pnpm install          # ставит зависимости + встроенный PostgreSQL, prisma generate
pnpm dev:all          # поднимает БД + next dev (или start.bat двойным кликом)
pnpm prod             # поднимает БД, собирает (только если менялся код) + next start
pnpm setup            # первичная настройка БД без запуска приложения
pnpm studio:all       # Prisma Studio с автоподъёмом БД
pnpm dev              # только dev-сервер (БД должна быть уже запущена)
pnpm db:push | db:seed | db:reset | db:studio | db:migrate-from-sqlite
pnpm lint
```

Тестовый аккаунт (только чистая установка с seed): `admin@csu.ru` / `admin123`.

### Обёртка `scripts/with-pg.mjs` (важно понимать)

Порядок работы при `dev:all` / `prod` / `setup`:
1. Создаёт `.env` из `.env.example` (секреты генерирует), если его нет.
2. Инициализирует `pgdata/` при первом запуске, стартует PostgreSQL на 5433.
3. Создаёт базу, **всегда** применяет схему (`prisma db push` — идемпотентно,
   чтобы после `git pull` со сменой schema.prisma колонки добавились).
4. Если БД пуста: перенос из старой SQLite (`SQLITE_DATABASE_URL`, напр.
   `file:./old/dev.db`) или seed.
5. В `--prod`: пропускает `pnpm build`, если отпечаток исходников в
   `.build-checksum` совпадает (см. `scripts/build-fingerprint.mjs`; форс
   пересборки — удалить `.build-checksum`).
6. По завершении (Ctrl+C) корректно останавливает БД.

Надёжность: осиротевшие после креша процессы embedded-PostgreSQL убиваются
(только процессы из `node_modules/embedded-postgres`!). Если порт 5433 занят
живой второй обёрткой или **внешним PostgreSQL-сервисом** (например, служба
Windows «PostgreSQL-Journal» на проде) — обёртка использует его и не трогает.
Если `DATABASE_URL` указывает не на `localhost:5433` — встроенный PG не
запускается вовсе.

## 7. Прод-сервер (состояние на сейчас)

- PostgreSQL крутится как **служба Windows «PostgreSQL-Journal»** на порту 5433
  из той же папки `pgdata/` проекта; бинарники службы — вне проекта
  (`C:\postgres\bin`), это важно, иначе обёртка примет службу за «свои» процессы.
- Приложение — `pnpm prod` (или задача планировщика `StudentsJournal`,
  ONSTART с задержкой 30 c, дергает `start-server.bat`). Обновление кода на
  сервере — скопировать файлы и перезапустить задачу: `schtasks /End /Run`.
- В `.env` на сервере: `NEXTAUTH_URL`/`AUTH_URL` = `http://tfcsu.ru:3000`,
  `AUTH_TRUST_HOST=true`. Порт 5433 наружу закрыт.
- Подробная инструкция: **DEPLOY-WINDOWS.md** (файрвол, NAT, диагностика).

## 9. Конвенции

- Весь UI, комментарии в коде и коммиты — **на русском**.
- Коммиты в стиле: `Фича: …`, `Фикс: …`, `Перевод: …` — кратко по-русски.
- Ничего из `/.env`, `/pgdata/`, `*.db`, `.build-checksum` не коммитится.
- Изменения схемы — правкой `prisma/schema.prisma` (+ `pnpm db:push` локально;
  на проде схему применит обёртка при следующем запуске).
- **Пакеты обновления «Для копирования N»** (по образцу Django-проекта
  расписания): когда изменения готовы к установке на прод, собери папку
  «Для копирования {следующий номер}» с ИЗМЕНИВШИМИСЯ файлами (структура
  путей сохраняется) + файл `ЧИТАЙ — что делать.txt` (что и куда копировать,
  нужны ли `pnpm install`/миграции — обычно нет: схему применит обёртка,
  пересборку определит отпечаток; как перезапустить — `schtasks /End /Run`)
  + одноимённый `.zip` (PowerShell `Compress-Archive`). Папку и zip закоммить
  и запушь в git. В инструкции отмечай внешние зависимости фичи (например,
  «для копирования 2» требует на сайте расписания пакет «для копирования 12»).

## 10. Известные грабли

- **`next dev`/`pnpm build` не запускаются из пути с `!`** (напр. `D:\!!Проекты\…`):
  webpack-валидация Next 14.2 отвергает `!` в абсолютных путях (контекст,
  output, правила next/font). Прод не страдает (путь `C:\Journal\…`). Обход для
  локальной проверки: копия/запуск из ASCII-пути без `!` (subst-диск и junction
  НЕ помогают — Node разрешает модули по реальному пути; работает только
  физическая копия с `pnpm install`).
- Встроенный PostgreSQL **нельзя** запускать от имени администратора Windows и
  из путей с кириллицей (на проде из-за этого и поднята отдельная служба).
- После `next dev` папка `.next` затирается dev-артефактами — отпечаток
  сборки это учитывает (сравнивается и BUILD_ID), prod пересоберётся сам.
- Порт 5433 выбран, чтобы не конфликтовать с обычным локальным PostgreSQL (5432).
  Смена — через `PG_EMBEDDED_PORT` + `DATABASE_URL`.
- Учётки: у User-студента доступ к чужим данным запрещён проверками роли
  (истор. коммит `2e2eef5` — не регрессировать).
