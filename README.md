# CSU Students Journal

Журнал/CRM для преподавателя — веб-приложение для учёта посещаемости и успеваемости студентов.

## Быстрый старт (клон → пара команд → работает)

База данных — **встроенный PostgreSQL**: бинарники скачиваются в `node_modules`
при установке зависимостей. Ничего устанавливать и настраивать отдельно не нужно.

```bash
# 1. Клонировать репозиторий
git clone https://github.com/rustam285/Students-Journal.git
cd Students-Journal

# 2. Установить зависимости (включая встроенный PostgreSQL)
pnpm install

# 3. Запустить
pnpm dev:all        # поднимет БД и запустит приложение в режиме разработки
# или
pnpm prod           # поднимет БД, соберет проект (build) и запустит production-сервер
```

На Windows то же самое — двойным кликом по **`start.bat`**.

Открой http://localhost:3000 в браузере.

При первом запуске всё настраивается автоматически:
- создаётся `.env` (секреты генерируются сами);
- инициализируется встроенный PostgreSQL (данные — в папке `pgdata/`);
- создаётся база и применяется схема;
- если указан старый SQLite-файл (см. ниже) — данные переносятся,
  иначе заливаются демо-данные.

Остановка: `Ctrl+C` — приложение и PostgreSQL завершатся корректно.
Если процесс был убит аварийно, следующий запуск сам подчистит осиротевшие
процессы БД и продолжит работу.

## Production-режим

Если вы хотите запустить проект в режиме production (как на реальном сервере, без пересборки страниц на лету), используйте:

```bash
pnpm prod
```

Эта команда автоматически:
1. Поднимет встроенный PostgreSQL и применит миграции.
2. Запустит `pnpm build` для оптимизации и сборки проекта.
3. Если сборка прошла успешно, запустит `pnpm start:all` (production-сервер).
4. При нажатии `Ctrl+C` корректно завершит и сервер, и базу данных.

## Перенос данных из старой SQLite-БД

Если у вас уже есть заполненная база на SQLite (`dev.db`) — вручную ничего
переносить не нужно:

1. Положите файл в папку `old/` проекта (например `old/dev.db`), **или** укажите
   путь в `.env`:
   `SQLITE_DATABASE_URL="file:C:/путь/к/Students-Journal/prisma/dev.db"`
2. Запустите `pnpm dev:all` или `pnpm prod` — при первом запуске данные
   перенесутся автоматически (пользователи, группы, студенты, предметы,
   занятия, оценки — с сохранением связей).

Перенос можно запустить и вручную: `pnpm db:migrate-from-sqlite`
(при уже поднятой БД: `pnpm setup` поднимет и перенесёт).

## Команды

| Команда                    | Описание                                              |
|----------------------------|-------------------------------------------------------|
| `start.bat` / `pnpm dev:all` | Запуск БД + приложения в режиме разработки          |
| `pnpm prod`                | Сборка (build) и запуск приложения с БД (production)  |
| `pnpm setup`               | Первичная настройка БД (без запуска приложения)       |
| `pnpm studio:all`          | Prisma Studio (с автозапуском БД)                     |
| `pnpm dev`                 | Только dev-сервер (БД должна быть уже запущена)       |
| `pnpm build`               | Сборка для продакшена                                 |
| `pnpm db:push`             | Применить схему Prisma к БД                           |
| `pnpm db:seed`             | Заполнить БД тестовыми данными                        |
| `pnpm db:reset`            | Сбросить и перезаполнить БД                           |
| `pnpm db:migrate-from-sqlite` | Перенести данные из старой SQLite-БД               |
| `pnpm lint`                | Проверка линтером                                     |

## Альтернативные варианты БД

- **Свой PostgreSQL/MySQL-совместимый сервер.** Укажите его адрес в
  `DATABASE_URL` — обёртка обнаружит внешний сервер и не будет запускать
  встроенный.
- **Docker:** `docker compose up -d` поднимет PostgreSQL 16 на порту 5432,
  после этого в `.env` укажите
  `DATABASE_URL="postgresql://journal:journal@localhost:5432/students_journal?schema=public"`.

## Структура данных

Встроенная БД хранит данные в папке `pgdata/` внутри проекта (в `.gitignore`).
Удалять её не нужно — там все ваши данные. Для полного сброса удалите папку
и запустите `pnpm setup`.

## Безопасность

- **НЕ** коммитить `.env`, `pgdata/` и файлы БД (`*.db`)
- Секреты аутентификации генерируются автоматически при создании `.env`
