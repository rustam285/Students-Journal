ЧТО ЭТО И ЗАЧЕМ
==============
Файлы из этой папки — обновление проекта Students-Journal (журнал студентов ЧелГУ),
которое нужно скопировать на прод-сервер (Windows Server, C:\Journal\Journal\Students-Journal).
Если путь на сервере другой — подставьте свой.

Что нового в этом обновлении:
  Автозаполнение журнала из расписания. Кнопка «Заполнить» есть на страницах
  ЖУРНАЛА и КАЛЕНДАРЯ. Выбираете период (сегодня / завтра / на дату / эта неделя /
  следующая неделя / две недели / месяц / с даты по дату) — откроется сводка
  «Проверьте, всё ли выбрано верно» (группа, преподаватель, период), и после
  подтверждения занятия создаются из расписания сайта ТФ ЧелГУ: только ваши
  пары, тема = дисциплина, предмет создаётся сам (если его ещё нет),
  посещаемость — всем «Присутствует». Повторное заполнение не создаёт дубликаты.

  Режим «Все мои группы»: одной кнопкой заполнить каждую группу, к которой
  у вас есть доступ (расписание скачивается один раз). Группы, которым не
  нашлось соответствия в расписании, перечисляются в результате.

  Сопоставление с расписанием подбирается автоматически (преподаватель по ФИО,
  группа по названию — без учёта регистра и е/ё). При несовпадении названий
  (например, журнал «ТФИ-101» — это расписание «Т1-ИТб-11») нужная группа
  выбирается вручную ОДИН раз и запоминается навсегда (по id, переименования
  на сайте расписания не страшны).

ВАЖНОЕ ОГРАНИЧЕНИЕ: кнопка полностью заработает только после того, как на сайте
расписания (http://tfcsu.ru:8100, тот же сервер) будет установлен пакет
«для копирования 12» (API /api/teachers/ и /api/teacher_schedule/).
Пока его нет, при заполнении появится ошибка связи — это ожидаемо.
Адрес API берётся из переменной SCHEDULE_API_URL (по умолчанию
http://127.0.0.1:8100 — для прода подходит, в .env на сервере менять НЕ нужно).


ШАГ 1. СКОПИРОВАТЬ ФАЙЛЫ
=======================
Скопируйте содержимое ЭТОЙ папки поверх папки проекта на сервере
(C:\Journal\Journal\Students-Journal), сохранив структуру:

  prisma\schema.prisma                          -> ...\Students-Journal\prisma\schema.prisma
  src\lib\schedule-api.ts                       -> ...\Students-Journal\src\lib\schedule-api.ts
  src\app\actions\schedule.ts                   -> ...\Students-Journal\src\app\actions\schedule.ts
  src\components\fill-journal-dialog.tsx        -> ...\Students-Journal\src\components\fill-journal-dialog.tsx
  src\app\(protected)\journal\page.tsx          -> ...\Students-Journal\src\app\(protected)\journal\page.tsx
  src\app\(protected)\calendar\page.tsx         -> ...\Students-Journal\src\app\(protected)\calendar\page.tsx
  scripts\with-pg.mjs                           -> ...\Students-Journal\scripts\with-pg.mjs
  scripts\build-fingerprint.mjs                 -> ...\Students-Journal\scripts\build-fingerprint.mjs
  package.json                                  -> ...\Students-Journal\package.json
  .env.example                                  -> ...\Students-Journal\.env.example

Пакет САМОДОСТАТОЧЕН: файлы обёртки (with-pg.mjs, build-fingerprint.mjs,
package.json) уже входят в него — не важно, устанавливалась ли ранее
«Для копирования 1». Если ставилась — эти файлы просто совпадают.

ВАЖНО: файл .env на сервере НЕ трогайте — его в этой папке нет, и он должен
остаться со своими паролями. Менять в нём ничего не нужно.

Новые зависимости НЕ появились — pnpm install на сервере запускать не нужно.
Схема базы меняется (два новых поля: сопоставления с расписанием) — вручную
применять ничего не нужно: обёртка при следующем запуске сама выполнит
prisma db push, как обычно.


ШАГ 2. ПЕРЕЗАПУСК
================
Перезапустите приложение, как при обычном обновлении:

  schtasks /End /Task StudentsJournal
  schtasks /Run /Task StudentsJournal

(или вручную: pnpm prod в папке проекта).

Первый запуск пересоберёт проект (код менялся, отпечаток сборки не совпадёт)
и применит схему БД, затем стартует как обычно.
