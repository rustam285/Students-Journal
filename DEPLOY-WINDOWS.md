# Публикация на Windows-сервере: доступ по домену tfcsu.ru:3000

Инструкция для прод-сервера, где настроено следующее:

- приложение (Next.js) запускается через `pnpm start` и слушает порт **3000**;
- PostgreSQL работает как **служба Windows** «PostgreSQL-Journal» на порту **5433** (данные — в папке `pgdata/` проекта);
- домен **tfcsu.ru** уже указывает (A-запись) на IP **178.46.164.93**.

Почему «на сервере открывается, а извне нет»: почти всегда это **файрвол Windows** —
он по умолчанию блокирует все входящие порты. Реже — сервер за NAT или приложение,
слушающее только 127.0.0.1. Ниже проверки по порядку.

## 1. Приложение слушает все интерфейсы

На сервере (пока приложение запущено):

```cmd
netstat -ano | findstr :3000
```

Должно быть `0.0.0.0:3000 LISTENING`. Если видите `127.0.0.1:3000` —
запускайте с флагом `pnpm start -- -H 0.0.0.0` (для этого проекта обычно не требуется:
`next start` по умолчанию слушает все интерфейсы).

## 2. Открыть порт 3000 в файрволе (ключевой шаг)

cmd **от имени администратора**:

```cmd
netsh advfirewall firewall add rule name="Students Journal 3000" dir=in action=allow protocol=TCP localport=3000
```

Проверить правило / удалить:

```cmd
netsh advfirewall firewall show rule name="Students Journal 3000"
netsh advfirewall firewall delete rule name="Students Journal 3000"
```

Больше для файрвола ничего не нужно: входящее правило одно (TCP 3000), Port 5433
открывать **не надо** — база должна быть доступна только с самого сервера.

## 3. Прямой IP или NAT?

```cmd
ipconfig
```

- Если среди адресов есть **178.46.164.93** — у сервера публичный IP напрямую,
  после шага 2 сайт уже должен открываться извне.
- Если только внутренние адреса (192.168.x.x, 10.x.x.x) — сервер за NAT.
  Тогда на роутере/шлюзе нужно **пробросить TCP 3000** на внутренний IP сервера
  (админ сети). Внешний IP сервера можно узнать, открыв с него в браузере
  `2ip.ru` — он должен совпасть с 178.46.164.93, иначе A-запись домена
  указывает на другую сеть (менять A-запись там, где управляется домен).

## 4. `.env`: вход по домену

На сервере в `.env` укажите адрес сайта, иначе после входа система может
редиректить на `localhost:3000`:

```env
NEXTAUTH_URL="http://tfcsu.ru:3000"
AUTH_URL="http://tfcsu.ru:3000"
```

(и оставьте `AUTH_TRUST_HOST=true`). После правки перезапустите приложение.

## 5. Проверка

- На сервере: `curl -I http://localhost:3000` и `curl -I http://178.46.164.93:3000`.
- Извне — с телефона **через мобильный интернет** (не из той же сети!):
  откройте `http://tfcsu.ru:3000`.
  - «вращается и timeout» → файрвол или NAT (шаги 2–3);
  - «не удаётся преобразовать имя» → проблема DNS;
  - открылось — готово.

## 6. Автозапуск приложения после перезагрузки

Bat-файл в папке «Автозагрузка» срабатывает **только при входе пользователя**:
после перезагрузки сервера (без RDP-входа) сайт лежит, пока кто-нибудь не войдёт.
Надёжнее — задача планировщика «при запуске системы» от вашего пользователя.

Создайте в папке проекта `start-server.bat`:

```bat
@echo off
cd /d C:\Journal\Journal\Students-Journal
call pnpm start
```

и зарегистрируйте задачу (cmd от администратора, подставьте пользователя и пароль):

```cmd
schtasks /Create /TN "StudentsJournal" /SC ONSTART /DELAY 0000:30 /TR "cmd /c C:\Journal\Journal\Students-Journal\start-server.bat" /RU КОМПЬЮТЕР\ПОЛЬЗОВАТЕЛЬ /RP ПАРОЛЬ /RL HIGHEST
```

`/DELAY 0000:30` — подождать 30 секунд после старта системы (служба PostgreSQL
успеет подняться). Управление задачей:

```cmd
schtasks /Run /TN StudentsJournal
schtasks /End /TN StudentsJournal
schtasks /Delete /TN StudentsJournal
```

Приложение запускается от вашего пользователя, поэтому pnpm/node найдутся так же,
как при ручном запуске. При обновлении кода: скопируйте изменённые файлы и
перезапустите задачу — `pnpm prod` сам пересоберёт проект (сборка выполняется
только при изменении кода, см. следующий раздел).

## 7. Запуск со службой PostgreSQL-Journal

Обёртка `with-pg.mjs` (команды `pnpm prod`, `start.bat`, `pnpm dev:all`) умеет
работать со службой: если порт 5433 занят PostgreSQL, запущенным не из
`node_modules/embedded-postgres`, обёртка использует его как внешний сервер —
не убивает и не останавливает. То есть на сервере снова можно пользоваться
`start.bat` / `pnpm prod`.

Сборка при этом не повторяется при каждом запуске: `pnpm prod` считает
отпечаток исходников (src, схема Prisma, конфиги) и сравнивает с сохранённым
после последней успешной сборки (файл `.build-checksum`). Код не менялся —
сборка пропускается и стартует сразу. Пересборка нужна только после смены кода
или зависимостей. Форсировать: удалить `.build-checksum`.

Один нюанс: убедитесь, что служба запущена из бинарников **вне** папки проекта
(например, `C:\postgres\bin`):

```cmd
sc qc PostgreSQL-Journal
```

в `BINARY_PATH_NAME` не должно быть `embedded-postgres`. Если там путь внутрь
`node_modules` — обёртка примет службу за «свои» процессы и будет конфликтовать:
перерегистрируйте службу на копию бинарников вне проекта.

## 8. Безопасность

- Порт **5433 наружу не открывать**: правило файрвола только для 3000/TCP.
- Сайт работает по HTTP без шифрования — логин/пароль передаются открытым
  текстом. Для внутренней сети допустимо; если позже понадобится HTTPS —
  ставится реверс-прокси (IIS или Caddy) на 80/443 порты, приложение
  остаётся на 3000.
